# Панели управления Xray: 3x-ui как альтернативный путь

Проект по умолчанию использует **Remnawave** (см. README, [`../DECISIONS.md`](../DECISIONS.md)
ADR-0001). Этот документ — для случая, если по своим причинам вы разворачиваете
на **3x-ui** вместо неё: чем отличается модель управления, что теряется, и как
использовать `api/xui_orchestrator.py`. Актуально на июль 2026.

---

## Кандидаты

| Проект | Что это | Статус |
|---|---|---|
| **3x-ui** (MHSanaei) | Монолит на Go: веб-панель и Xray-core в одном процессе | Активно развивается |
| **Marzban** (Gozargah) | Панель + ноды, Python/FastAPI | Разработка практически остановилась |
| **Marzneshin** | Форк Marzban с переработанной архитектурой нод | Живой, но экосистема меньше |
| **Remnawave** | Панель (NestJS + React) + ноды (Remnanode), микросервисы, Postgres | Активно развивается, один мейнтейнер |

---

## Ключевое отличие: модель пользователя

### 3x-ui: пользователь привязан к inbound на конкретном сервере

```
Сервер RU  →  3x-ui #1  →  inbound  →  [Иван] [Пётр] [Анна]
Сервер FR  →  3x-ui #2  →  inbound  →  [Иван] [Пётр] [Анна]   ← заводить заново
Сервер DE  →  3x-ui #3  →  inbound  →  [Иван] [Пётр] [Анна]   ← заводить заново
Сервер NL  →  3x-ui #4  →  inbound  →  [Иван] [Пётр] [Анна]   ← заводить заново
Сервер KZ  →  3x-ui #5  →  inbound  →  [Иван] [Пётр] [Анна]   ← заводить заново
```

Цена операций при 100 пользователях и 5 серверах:

| Операция | Действий |
|---|---|
| Добавить одного человека | 5 |
| Удалить одного человека | 5 |
| Продлить всем подписку | 500 |
| Ротация ключей после утечки | 500 |
| Сверка «кто где есть» | 5 выгрузок + ручная диффка |

С оркестратором (`api/xui_orchestrator.py`) это управляемо, но добавляет
распределённую систему с проблемой согласованности: если одна панель была
недоступна в момент массовой операции, состояние расходится, и узнать об этом
можно только сверкой — отсюда обязательный `reconcile()`.

### Remnawave: пользователь → сквад → множество нод

```
                       ┌─ нода FR ─┐
[Иван] ─→ сквад «EU» ──┼─ нода DE ─┤
                       └─ нода NL ─┘

[Пётр] ─→ сквад «Все» ─→ FR + DE + NL + KZ + RU
```

| Операция | Действий |
|---|---|
| Добавить одного человека | 1 |
| Удалить одного человека | 1 |
| Продлить всем подписку | 1 запрос в цикле, состояние консистентно |
| Ротация ключа одного человека | 1 (`revoke`) |
| Смена страны выхода для группы | 1 (переназначить сквад) |

## Что теряется при переходе на 3x-ui

Если сценарий — 5 серверов (RU-вход + FR/DE/NL/KZ выходы), это конкретно
означает:

- Мультисерверность реализуется собственным оркестратором
  (`api/xui_orchestrator.py`), а не встроенной моделью «сквад».
- Панель = узел: на каждом сервере, включая российский, полноценная панель с
  БД. Если RU-сервер изымут или он окажется скомпрометирован, вместе с ним
  уходит база пользователей этого узла.
- Нода не работает без панели (в отличие от Remnanode).
- Нет HWID-лимита устройств — только `limitIp` (лимит одновременных IP, не то же самое).
- Нет вебхуков — только опрос через API.
- Сквозной статистики по трафику нет: `collect_traffic()` в оркестраторе
  суммирует по всем панелям, но для транзитной схемы цифра завышена примерно
  вдвое (трафик считается и на входной RU-ноде, и на выходной).

Компенсирующие факторы: меньше ресурсов на панель (~256 МБ против ~2 ГБ),
мульти-админ из коробки, весь стек — в одном процессе, что упрощает отладку
для небольших инсталляций (≤2 сервера, ≤15 пользователей).

## Как использовать 3x-ui вместо Remnawave

`api/xui_orchestrator.py` — веерные операции по N панелям 3x-ui с одним и тем
же UUID клиента на всех. Обязательно реализовать регулярный `reconcile()` —
без сверки состояния распределённая ручная схема расходится в течение недель
незаметно для оператора.

## Миграция

| Откуда | Куда | Как |
|---|---|---|
| Marzban | Remnawave | Официальный гайд миграции в документации |
| 3x-ui | Remnawave | Готового инструмента нет. Выгрузить клиентов через API 3x-ui, создать через API Remnawave. При сохранении UUID и параметров inbound клиенты не заметят перехода |
| Любая | Голый Xray | Конфиги в `../configs/` — рабочие без панели вообще |

Последняя строка — не запасной вариант на бумаге, а реальная страховка. Панель
управляет конфигурацией; трафик носит Xray. Если панель по любой причине
станет недоступна, рабочие конфиги остаются на руках.
